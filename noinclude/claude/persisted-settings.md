# Persisted, cross-tab-synced reader settings (theme, font size, ...)

The reader side of a persisted setting is covered in [extension/reader/docs/persisted-settings.md](../../extension/reader/docs/persisted-settings.md): the absolute setter vs. the user-initiated action that saves, startup restore via `useSaved<Setting>()` in `applyAllSavedSettings()`, and storage only through `g.hostAdapter.getSetting/saveSetting`. Read it first. This file covers the extension side.

The reader UI is not an iframe — `content.js`'s `showReaderOverlay()` splices `reader.html` directly into each qualifying tab's own document, so every tab runs its own independent reader instance. A setting therefore needs to persist across reloads, apply on startup, and live-sync to every other open reader tab. `theme`, `fontSize`, `fontSet` and `favorites` are implemented this way today — use them as the template.

1. **Storage:** persisted in `chrome.storage.local` under its own top-level key (not real `window.localStorage` — the reader runs in the page's own MAIN-world origin, which has no `chrome.*` access). [extension/adapter/HostAdapter.js](../../extension/adapter/HostAdapter.js)'s `getSetting`/`saveSetting` `window.postMessage` to the content script; the actual `chrome.storage.local.get/set` calls happen in [extension/bridge.js](../../extension/bridge.js)'s `SAVE_OBJECT_IN_LOCAL_STORAGE`/`GET_OBJECT_FROM_LOCAL_STORAGE` handlers. A new key needs no changes here.
2. **Cross-tab broadcast:** in [extension/bridge.js](../../extension/bridge.js), a single `chrome.storage.onChanged` listener (gated on `area === 'local'` and `isShowingReader`) checks `changes.<key>` and `window.postMessage`s a `<SETTING>_CHANGED` message into that tab's reader page — add a new `if (changes.<key>) {...}` branch alongside the existing ones rather than a new listener. `chrome.storage.onChanged` fires in every tab's `bridge.js` instance (not just the one that wrote the change) — this is Chrome's native broadcast, so no `chrome.tabs.query`/`sendMessage` fan-out via `background.js` is needed.
3. **Receiving the broadcast:** in `HostAdapter.initReader()`'s `window.addEventListener("message", ...)` handler, add a `<SETTING>_CHANGED` branch that calls the reader's absolute setter with saving disabled (never true), guarded by comparing to the current in-memory value first to skip redundant DOM work in the tab that originated the change (that tab receives its own broadcast too, since Chrome doesn't distinguish the writer).
4. **Settings changed from the popup** (theme, font set, favorites in [extension/popup.js](../../extension/popup.js)) are sent as `SetTheme`/`SetFontSet`/`SetFavorites` messages to the active tab's [extension/content.js](../../extension/content.js), which saves them to `chrome.storage.local` and also posts the `<SETTING>_CHANGED` message to its own page directly. Other tabs get the change through the broadcast above.
